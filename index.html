🚨 Novo M.O. — ATO & Fraudulent Access (App Cloned)
Antes de negar um caso de ATO/Acesso Fraudulento, confira o Widget Challenge Platform (use CTRL+F e busque "App Cloned") olhando a data próxima à transação.

Se encontrar esse evento, NÃO finalize o caso:
  1. Deixe o caso em Ação Solicitada
  2. Use a macro CSS2 - CSS - CSI STATUS - Em análise
  3. Escale para o 2nd Level via Jira, com print do evento anexado
🧪 Novo teste — ATO com autenticação por OTP
Quando aplicar: sempre que, na contestação, o último auth de device do cliente tiver sido via OTP (código por SMS/WhatsApp) em vez de Liveness.

Antes de abrir o incidente, pergunte: "Você recebeu algum código de autenticação hoje?"
  1. Se SIM: quem solicitou o código, em qual canal chegou (SMS/WhatsApp), e se recebeu ligação/orientação de alguém dizendo ser do Nubank ou compartilhou o código
  2. Se NÃO: se trocou chip/fez portabilidade recentemente, se ficou sem sinal/SMS, ou teve problema no WhatsApp
No Backoffice: reembolse/acate o caso — desfecho padrão durante o teste. Adicione a tag [Auth-OTP] + link do comunicado no comentário do incidente.

⚠️ Contestações desse grupo (inclusive controle) passam por análise manual — não finalizar automaticamente.
